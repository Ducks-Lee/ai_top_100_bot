  - AI 결과를 검수해 바로잡은 것: <예) LLM이 데이터에 없는 값을 답한 경우를 찾아 코드 규칙으로 막음>

## 4. 강점
1. **정답이 있는 처리는 코드가 합니다.** LLM은 사용자의 말을 해석해 의도와 값을 뽑는 데만 쓰고, 계산·집계·규칙 검증·권한 판단·답변 문장은 Python이 합니다. 그래서 같은 질문에 같은 답이 나오고, 데이터에 없는 수치를 지어내지 않습니다.
2. **안 될 때도 이유와 대안을 말합니다.** 불가·확인 필요로 답할 때 이유와 함께 코드가 계산한 대안(<가장 가까운 가능 날짜·수량, 비슷한 상품 등>)을 제시합니다. <대화 예: "○○는 품절이에요. 같은 날 △△는 5개 남았어요">
3. **악성 요청을 구조로 막습니다.** LLM이 낸 의도·값은 미리 정한 목록과 형식을 통과해야 쓰입니다. 메시지 속 "규칙을 무시해" 같은 지시로 새 기능이나 권한이 생기지 않고, 타인·다수 정보는 권한을 주장하는 것만으로는 주지 않습니다. <대화 예: 사칭·명단 요청에 대한 실제 답>
4. **현장 어르신도 쓰기 쉽게 만들었습니다.** 사용자가 나이 많은 농수산물 현장 종사자일 수 있어(<인터뷰 근거>) 존댓말과 현장 용어(<예: 물건, 상자>)로 결론부터 짧게 답합니다. 오타·사투리·"낼모레" 같은 말도 알아듣고, 날짜는 코드가 계산해 "11월 3일(월)"처럼 요일까지 보여 줍니다. 선택지는 버튼으로 눌러 고르고, <예약·취소> 같은 일은 내용을 요약해 "네"를 받은 뒤에만 처리해 실수를 막습니다. <대화 예>
5. **모르면 모른다고 하고 되묻습니다.** 필요한 값이 빠지면 받은 값을 먼저 데이터와 대조한 뒤, 필요한 것만 되묻습니다. 대화 상태는 사용자별로 나눠 여러 사람이 동시에 써도 섞이지 않습니다.
6. **운영진 액션 서버와 연동했습니다.** <어떤 동작을 API로 처리하는지>. 응답은 코드가 해석하고, 실패하면 결과를 꾸며내지 않고 다시 시도할 방법을 안내합니다. 예약처럼 상태를 바꾸는 요청은 중복 처리를 막기 위해 시간 초과 뒤 다시 보내지 않습니다.
7. **심사 기간 내내 응답하도록 운영합니다.** AWS EC2에서 상시 접속(게이트웨이 방식)으로 돌고, 끊기면 자동으로 다시 접속합니다. 답장 실패·접속 끊김·LLM 이상이 생기면 운영자인 저에게 디스코드로 장애 알림이 와서 바로 상태를 확인할 수 있습니다(사용자에게 가는 알림이 아닙니다). 메시지당 응답은 보통 <n>초입니다.

## 5. 설계 방식
- 기술 구성 (골랐던 이유와 함께, 실제로 쓴 것만 남긴다):
  - LLM: Anthropic Claude API(`<llm.MODEL 값>`, 메시지당 1회, 구조화 출력). 해석만 맡기고 결과 형식을 JSON 스키마로 강제해 코드가 검증할 수 있게 했습니다.
  - 언어·라이브러리: Python, `anthropic` SDK, `httpx`(비동기 HTTP), `websockets`. 웹 프레임워크와 DB 서버 없이, 데이터는 시작할 때 메모리(dict)에 올려 조회합니다.
  - 카카오 연동: 카카오톡 봇 API 게이트웨이(웹소켓) 방식 + 메시지 콜백 API. 서버가 먼저 접속하므로 도메인·HTTPS·인바운드 포트가 필요 없습니다.
  - 운영진 액션 서버: <쓴 API와 용도>
  - 운영: AWS EC2(<인스턴스 유형>, 서울 리전) + systemd 자동 재시작, 운영자용 디스코드 장애 알림. 여러 사용자의 메시지를 동시에 처리하고, 대화 상태는 사용자별로 나눕니다.
  - 개발 도구: Claude Code로 구현, Codex로 교차 검토, pytest로 시나리오 자동 시험
- 흐름: 카카오톡 메시지 → LLM 1회(구조화 출력으로 의도·값·대상 범위 추출) → Python 결정(권한 → 필수 값 → 형식 검증 → 처리 또는 되묻기) → <액션 서버 호출> → 템플릿 답변
- 의도: <의도 목록과 각 처리>
- 데이터: <받은 자료 → 검증·정제한 내용(중복, 누락, 형식 통일, 기준 시점)>. 봇이 시작할 때 메모리에 올려 메시지마다 다시 읽지 않습니다.
- 권한: <본인 정보만 / 관리자 확인 방법>
- 답변: 카카오톡에 맞게 500자 이내(목표 200~300자), 마크다운 없이, 쉬운 말과 현장 용어로 씁니다. 선택지와 확인은 버튼으로 받습니다.
- 사용자 배려: 오타·사투리·구어 입력 해석(LLM) + 상대 날짜 계산(Python), 한 번에 하나만 예시와 함께 묻기, 상태를 바꾸는 일은 요약 후 확인, 해결 못 하면 <담당자 연락 방법> 안내
- 실패 처리: LLM 시간 초과(30초, 재시도 1회), 요청 과다, 형식 오류마다 다른 안내 문구를 둡니다.

1. 인터뷰(<시각>까지): 관계자별로 업무·예외·충돌을 묻고, 말과 자료가 다르면 자료를 확인한 뒤 규칙으로 정했습니다.
