# 용어집

이 프로젝트에 나오는 용어를 분야별로 정리했다. 각 항목 끝의 **이 프로젝트에서**는 해당 용어가 코드나 설정의 어디에 쓰이는지 알려 준다. 전체 구조는 [아키텍처](architecture.md)에서 볼 수 있다.

- [통신 방식](#통신-방식): 웹훅, 게이트웨이, 웹소켓, HTTPS
- [카카오 게이트웨이 프로토콜](#카카오-게이트웨이-프로토콜): Opcode, 핸드셰이크, HEARTBEAT, RESUME, close code
- [카카오톡 봇 API](#카카오톡-봇-api): 토큰, 콜백 API, SkillResponse
- [Python 비동기 프로그래밍](#python-비동기-프로그래밍): asyncio, 태스크, 타임아웃, 블로킹
- [안정성 설계](#안정성-설계): 지수 백오프, 일회용 토큰, graceful shutdown
- [AWS와 서버 운영](#aws와-서버-운영): EC2, 스왑, 탄력적 IP, 보안 그룹, systemd, 로그
- [기타](#기타): 환경변수, 에이전트, Mermaid

## 통신 방식

### 웹훅
Webhook. **상대 서버가 이벤트가 생길 때마다 내 서버의 URL로 HTTP 요청을 보내 주는 방식**이다. "일이 생기면 이 주소로 알려 줘"라고 주소를 등록해 두는 것과 같다.
- 장점: 내 서버는 요청을 받기만 하면 된다. 서버리스 환경에도 잘 맞는다.
- 단점: 외부에서 접속할 수 있는 공개 주소가 필요하다. 카카오는 [HTTPS](#https와-tls-인증서)만 허용하므로 도메인과 인증서도 있어야 한다. 요청이 진짜 카카오에서 왔는지도 직접 검증해야 한다.
- 비교: [게이트웨이](#게이트웨이)

**이 프로젝트에서**: 예비용 `main.py`가 웹훅 방식이다. 지금은 배포하지 않는다.

### 게이트웨이
Gateway. 카카오톡 봇 API에서는 **봇 서버가 카카오 서버(`wss://bot-gateway.kakao.com/gateway`)에 먼저 [웹소켓](#웹소켓)으로 접속해 연결을 유지하고, 그 연결로 이벤트를 받는 방식**을 말한다.
- 장점: 내 서버가 바깥으로 접속만 하면 된다. 그래서 공개 주소, 도메인, 인증서, 인바운드 포트가 필요 없다.
- 단점: 연결 유지([HEARTBEAT](#heartbeat와-heartbeat_ack))와 재연결([RESUME](#resume과-session_id-seq))을 직접 구현해야 한다. 서버가 계속 켜져 있어야 한다.
- 웹훅 URL을 등록해 두면 게이트웨이를 쓸 수 없다. 둘 중 하나만 고른다.

**이 프로젝트에서**: `gateway.py`. 현재 채택한 방식이다.

### 웹소켓
WebSocket. **한 번 연결해 두면 양쪽이 언제든 메시지를 주고받을 수 있는 통신 방식**이다. 일반 HTTP는 "요청 한 번, 응답 한 번"으로 끝나지만, 웹소켓은 전화처럼 연결이 계속 유지된다. 주소는 `ws://`(암호화 없음)나 `wss://`(TLS 암호화)로 시작한다.

**이 프로젝트에서**: `websockets` 라이브러리로 카카오 게이트웨이에 `wss://`로 접속한다.

### HTTP 요청과 상태 코드
HTTP는 웹의 기본 요청/응답 규칙이다. 응답에 붙는 세 자리 숫자를 상태 코드라고 한다.
- `200 OK`: 성공(본문 있음)
- `204 No Content`: 성공(본문 없음)
- `400 Bad Request`: 요청 형식이 잘못됨
- `401 Unauthorized`: 인증 실패
- `500 Internal Server Error`: 서버 내부 오류
- "2xx"는 200번대 전체(성공)를 뜻한다.

**이 프로젝트에서**: 콜백 API가 `200`을 돌려주면 답장 성공이다. 웹훅 방식이었다면 `204`로 수신 확인을 해야 했다.

### HTTPS와 TLS 인증서
HTTPS는 HTTP에 **TLS 암호화**를 더한 것이다. TLS를 쓰려면 서버에 **인증서**가 필요하다. 인증서는 "이 서버가 진짜 `example.com`이 맞다"는 것을 공인 기관(CA)이 보증하는 문서다.
- 공인 인증서는 보통 **도메인 이름**에 대해 발급된다. 그래서 "HTTPS가 필요하면 도메인 이름이 필요하다"고 말한다.
- 스스로 만든 인증서(self-signed)는 무료지만, 외부 서버는 이를 신뢰하지 않는다.
- Let's Encrypt는 무료 공인 인증서를 자동으로 발급해 주는 기관이다.
- **443번 포트**는 HTTPS가 관례적으로 쓰는 포트 번호일 뿐이다. 443을 연다고 해서 HTTPS가 되지는 않는다. HTTPS가 되려면 그 포트에서 신뢰받는 인증서로 TLS를 처리해야 한다.

**이 프로젝트에서**: 게이트웨이 방식이라 EC2에는 인증서가 필요 없다. EC2가 카카오로 접속할 때 쓰는 `wss://`와 `https://`의 인증서는 카카오 쪽 서버가 가지고 있다.

### 도메인과 DNS
도메인은 `bot.example.com`처럼 사람이 읽기 쉬운 서버 이름이다. DNS는 이 이름을 IP 주소로 바꿔 주는 전화번호부 역할을 한다.
- sslip.io나 DuckDNS 같은 서비스를 쓰면 무료로 도메인 이름을 얻을 수 있다.

### 리버스 프록시
Reverse proxy. 바깥 요청을 먼저 받아서 안쪽 앱에 전달하는 중간 서버다. HTTPS 처리를 대신 맡는 경우가 많다. Caddy와 Nginx가 대표적이다. Caddy는 Let's Encrypt 인증서를 자동으로 발급하고 갱신해 준다.

**이 프로젝트에서**: 웹훅 방식일 때만 필요하다(`deploy/webhook/Caddyfile`).

### 인바운드와 아웃바운드
인바운드는 바깥에서 내 서버로 들어오는 연결이고, 아웃바운드는 내 서버에서 바깥으로 나가는 연결이다. 방화벽은 보통 인바운드를 엄격하게 막는다.

**이 프로젝트에서**: 게이트웨이는 아웃바운드 연결만 쓴다. 그래서 인바운드는 SSH(22번)만 열면 된다.

## 카카오 게이트웨이 프로토콜

### Opcode
게이트웨이에서 오가는 모든 메시지(프레임)는 `{"op": 숫자, ...}` 형식의 JSON이다. `op`는 프레임의 종류를 나타내는 번호다.

| op | 이름 | 방향 | 의미 |
|---|---|---|---|
| 0 | DISPATCH | 카카오 → 봇 | 이벤트 전달 |
| 1 | HEARTBEAT | 봇 → 카카오 | "나 살아 있어요" |
| 2 | IDENTIFY | 봇 → 카카오 | 처음 인증 |
| 3 | READY | 카카오 → 봇 | 인증 성공 |
| 6 | RESUME | 봇 → 카카오 | 끊긴 세션 이어받기 |
| 10 | HELLO | 카카오 → 봇 | 접속 직후 인사 |
| 11 | HEARTBEAT_ACK | 카카오 → 봇 | HEARTBEAT 받았음 |

**이 프로젝트에서**: `gateway.py`의 `OP_*` 상수.

### 핸드셰이크 (HELLO → IDENTIFY → READY)
연결 직후 서로를 확인하는 절차다.
1. 카카오가 HELLO를 보낸다. 여기에 HEARTBEAT를 보낼 주기(`heartbeat_interval`, 기본 41.25초)가 들어 있다.
2. 봇이 IDENTIFY에 [봇 인증 토큰](#봇-인증-토큰)을 담아 보낸다.
3. 카카오가 READY와 `session_id`를 보낸다. 이때부터 이벤트(DISPATCH)가 들어온다.

**이 프로젝트에서**: `Gateway._connect_once()`.

### DISPATCH와 이벤트 종류
DISPATCH(op 0)는 채팅방에서 일어난 일을 알려 주는 프레임이다. `t`는 이벤트 종류, `d`는 내용, `s`는 순번이다.
- `MESSAGE_CREATE`: 사용자가 메시지를 보냄. **답장 대상은 이것뿐이다.**
- `ENTRANCE`: 봇이 채팅방에 들어감
- `CHAT_JOIN`: 사용자가 채팅방에 들어옴
- `LEAVE`: 봇이 채팅방에서 나감
- `AD_REWARD`: 사용자가 광고 리워드를 받음

**이 프로젝트에서**: `bot.handle_event()`가 `MESSAGE_CREATE`에만 답하고, 나머지 이벤트는 종류만 `event ignored type=...` 로그로 남긴다. 이미 대화한 계정으로 채팅방을 나갔다 들어오기, 삭제 후 새로 시작, 채널 친구 추가, 차단 후 해제를 해도 `CHAT_JOIN`, `ENTRANCE`는 오지 않았다(10/28 실측, 처음 들어오는 계정은 확인 안 함). 그래서 첫 인사는 입장 이벤트가 아니라 사용자의 첫 메시지에 붙인다(`agent.with_intro`).

### HEARTBEAT와 HEARTBEAT_ACK
연결이 살아 있는지 확인하는 신호다. 봇이 주기적으로 HEARTBEAT를 보내면 카카오가 ACK로 답한다.
- 봇이 90초 넘게 HEARTBEAT를 보내지 않으면 카카오가 연결을 끊는다(4009).
- 반대로 ACK가 오지 않으면 연결이 겉으로만 살아 있는 상태일 수 있다. 그래서 봇이 스스로 끊고 다시 붙는다.

**이 프로젝트에서**: `Gateway._heartbeat()`. 주기의 90%마다 보내고, 다음 차례까지 ACK가 없으면 재연결한다.

### RESUME과 session_id, seq
연결이 끊겼을 때 **처음부터 다시 인증하지 않고, 이전 세션을 이어받는** 방법이다.
- `session_id`: READY에서 받은 세션 이름
- `seq`(`s`): 마지막으로 받은 DISPATCH의 순번
- RESUME에 이 두 값을 보내면, 카카오가 그 뒤에 놓친 이벤트를 이어서 보내 준다. 다만 연결마다 최근 100개까지만 보관한다.

**이 프로젝트에서**: `Gateway.session_id`, `Gateway.last_seq`.

### close code
웹소켓 연결을 닫을 때 붙는 이유 번호다.

| 코드 | 의미 | 봇의 대응 |
|---|---|---|
| 1001 | 서버 재시작 | RESUME |
| 4001 | 인증 실패 | 5분 뒤 새로 IDENTIFY (토큰 확인) |
| 4003 | 잘못된 페이로드 | 종료 (코드 버그) |
| 4004 | 다른 연결로 대체됨 (문서상. 실측에서는 중복 접속해도 오지 않았다) | 60초 뒤 새로 IDENTIFY (중복 실행 확인) |
| 4009 | 세션 만료 (`Session unavailable`) | 새로 IDENTIFY. RESUME이 거절된 경우면 바로 |

**이 프로젝트에서**: `FATAL_CLOSE_CODES`, `CLOSE_AUTH_FAILED`, `CLOSE_REPLACED`, `CLOSE_SESSION_EXPIRED`. 카카오 문서는 4004에서 종료하라고 하지만, 운영 봇이 꺼진 채 남지 않도록 재접속하게 했다. 4001도 카카오 쪽 일시 오류일 수 있어서 종료하지 않고 5분 간격으로 재시도한다.

## 카카오톡 봇 API

### 봇 인증 토큰
`BOT_TOKEN`. 봇을 만들면 발급되는 **봇 전용 비밀 키**다. 게이트웨이에 접속하거나 봇 API를 호출할 때 `Authorization: KakaoAK <토큰>` 형식으로 쓴다. 남이 알면 내 봇으로 메시지를 보낼 수 있으므로 절대 공개하지 않는다.

**이 프로젝트에서**: `.env`의 `BOT_TOKEN`.

### 콜백 토큰
`callbackToken`. DISPATCH 이벤트(`d.callbackToken`)에 담겨 오는, **그 메시지에 답장할 수 있는 일회용 허가증**이다.
- 받은 뒤 **5분이 지나면 만료**된다.
- 한 번 쓰면 끝이다(일회용). 그래서 이미 전송됐을 수도 있는 요청은 다시 보내지 않는다.

**이 프로젝트에서**: `bot.handle_message()`가 만료 시각을 계산하고, `bot.send_reply()`가 사용한다.

### 메시지 콜백 API
`POST https://kapi.kakao.com/v1/bot/callback`. **받은 메시지에 답장을 보내는 API**다. 봇 인증 토큰과 콜백 토큰을 헤더에 넣고, 본문에 [SkillResponse](#skillresponse)를 담는다. 게이트웨이와 웹훅 모두 답장은 이 API로 보낸다.

**이 프로젝트에서**: `kakao.send_callback()`.

### 메시지 전송 API
`POST https://kapi.kakao.com/v1/bot/send_message`. 사용자가 말을 걸지 않았는데 **봇이 먼저 보내는** 메시지에 쓰는 API다. 하루 1,000건으로 제한되고, 광고는 금지다. 채널채팅에서는 그 채널을 친구로 추가한 사용자에게만 보낼 수 있다(아니면 `-877`, 10/28 실측). 심사자가 친구라는 보장이 없어 이 프로젝트에서는 쓰지 않는다.

### SkillResponse
카카오 봇 응답의 JSON 형식이다(버전 `"2.0"`). 기존 카카오 i 오픈빌더와 같은 형식을 쓴다.
```json
{"version": "2.0", "template": {"outputs": [{"simpleText": {"text": "안녕하세요"}}]}}
```
- `outputs`: 말풍선 1~3개
- 말풍선 종류: `simpleText`(글자, 최대 1,000자), `simpleImage`, `basicCard`, `listCard`, `carousel` 등
- `quickReplies`: 문서 설명은 "채널채팅에서 봇이 응답할 때 다음 액션이나 발화를 제안"하는 빠른 답장 목록(최대 10개)이다. "이해하기" 문서 그림에는 마지막 말풍선 바로 아래에 둥근 버튼이 한 줄로 그려져 있다. **콜백으로 보냈을 때 채널채팅에 보이지 않았다**(10/28 실측, 오류도 없음).
- 카드 버튼: `message`(글자 보내기), `webLink`(주소 열기) 등. 버튼 글자는 14자까지다. `message` 버튼을 누르면 버튼의 `messageText`가 사용자가 직접 보낸 것처럼 일반 메시지로 온다(10/28 실측). 채널채팅에서는 명령어를 쓸 수 없고 퀵리플라이도 보이지 않았으므로, 지금 확인된 다음 질문 안내 수단은 이 버튼이다.

**이 프로젝트에서**: 에이전트가 문자열을 돌려주면 `kakao.text_response()`가 simpleText 하나짜리 응답을 만든다. 더 풍부하게 답하려면 `kakao.skill_response([kakao.simple_text(...), kakao.suggestion_card(["질문1", "질문2"])])`처럼 돌려준다. 카카오는 개수나 길이가 넘쳐도 오류 없이 버리므로 `kakao.limit_response()`가 보내기 전에 잘라 경고한다. 여러 건은 `kakao.list_card(제목, [kakao.list_item(...)], [버튼])`로 보여 줄 수 있다(항목 최대 5개, 항목을 누르면 지정한 글자가 메시지로 감). 퀵리플라이가 들어 있으면 빼고 경고한다. 카드 형식이 틀려 카카오가 거절하면 글자만 모아 다시 보낸다(로그 `callback=fallback`). 다만 카카오는 틀린 형식도 거절하지 않고 받는 경우가 많아서(10/28 실측) 이 장치는 드물게만 동작한다. `callback=ok`도 화면에 제대로 보였다는 뜻은 아니므로, 새 답장 모양은 휴대폰 화면으로 직접 확인한다.

### botGroupKey와 botUserKey
`botGroupKey`는 채팅방을, `botUserKey`는 사용자를 구분하는 키다. 대화 기록을 사람별, 방별로 저장할 때 쓸 수 있다.

### 호출 허용 IP
카카오 디벨로퍼스의 [어드민 키] 설정에 등록하는 **봇 API를 호출할 수 있는 서버 IP 목록**이다. 봇 인증 토큰이 유출돼도 다른 곳에서 호출하지 못하게 막는 보안 장치다.
- 목록이 **비어 있으면 모든 IP가 허용된다.** 카카오 봇 문서는 "필수"라고 적지만, 2026-10-27 실측에서는 아무것도 등록하지 않아도 콜백이 성공했다.
- **하나라도 등록하면 목록에 있는 IP만 허용된다.** 목록에 없는 IP에서 보낸 콜백은 `ip mismatched` 오류(-401)로 거부된다.

**이 프로젝트에서**: 보안을 위해 EC2의 [탄력적 IP](#탄력적-ip)를 등록한다. 등록하면 로컬 PC에서 보내는 답장도 막히므로, 로컬 테스트를 계속하려면 지금 PC의 공인 IP도 함께 넣는다.

### 카카오톡 채널
카카오톡 안의 비즈니스 계정이다. 봇을 만들면 채널이 자동으로 생기고, 봇은 이 채널을 프로필로 쓴다. 대회 안내에 따라 채널은 검색되지 않게 설정한다.

## Python 비동기 프로그래밍

### 비동기(async/await)
기다리는 동안 다른 일을 하는 프로그래밍 방식이다. 네트워크 응답을 기다리는 동안 CPU가 놀지 않고 다른 메시지를 처리할 수 있다. `async def`로 정의한 함수(코루틴)는 `await`로 호출한다.

### asyncio와 태스크
`asyncio`는 Python의 비동기 실행 도구다. **태스크(Task)**는 백그라운드에서 동시에 돌아가는 작업 단위로, `asyncio.create_task()`로 만든다.

**이 프로젝트에서**: 게이트웨이는 이벤트를 받을 때마다 태스크를 만든다(`Gateway._spawn()`). 그래서 답변 하나가 오래 걸려도 다음 메시지를 계속 받을 수 있다. HEARTBEAT 전송과 이벤트 수신도 각각 별도 태스크로 동시에 돈다.

### 타임아웃
정해진 시간 안에 끝나지 않으면 작업을 포기하는 것이다. `asyncio.wait_for(작업, 초)`는 시간이 넘으면 `TimeoutError`를 일으킨다.

**이 프로젝트에서**: 에이전트 답변 생성에 시간 예산을 걸어, 콜백 토큰이 만료되기 전에 반드시 무언가 답장하도록 한다.

### 이벤트 루프 블로킹
asyncio는 **스레드 하나**가 여러 작업을 번갈아 처리한다(이 실행 장치를 이벤트 루프라고 한다). 작업이 `await`에서 기다리는 동안 다른 작업으로 넘어가는 방식이다. 그래서 어떤 작업이 `await` 없이 오래 붙잡고 있으면(`time.sleep()`, `requests.get()`, 동기 SDK 호출) 그동안 **모든 작업이 멈춘다**. 이것을 블로킹이라고 한다.

**이 프로젝트에서**: 메인 루프는 게이트웨이 연결(HEARTBEAT, 이벤트 수신)을 맡는다. 에이전트가 메인 루프를 멈추면 HEARTBEAT가 끊겨 카카오가 연결을 닫는다. 그래서 `bot.py`의 `AgentRunner`가 에이전트를 메인 루프 밖에서 돌린다.
- `async def reply`: 별도 스레드의 전용 루프에서 실행한다. 안에서 실수로 동기 호출을 해도 연결은 유지되지만, 다른 사용자의 답변은 함께 멈춘다. 2초 이상 멈추면 그 즉시 `agent loop blocked` 경고가 로그에 남는다.
- `def reply`: 요청마다 스레드를 하나씩 띄워 실행한다. 동기 SDK를 쓸 때는 이쪽이 안전하다.
- 어느 쪽이든 시간 예산이 지나면 사용자에게는 대체 답변이 가지만, 이미 시작된 동기 호출은 강제로 멈출 수 없다. 그래서 LLM SDK에는 꼭 타임아웃을 설정한다.

### 경쟁 상태와 사용자별 잠금
여러 작업이 같은 데이터를 동시에 읽고 고치면, 실행 순서에 따라 결과가 달라지거나 고친 내용이 사라질 수 있다. 이것을 경쟁 상태(race condition)라고 한다. 잠금(lock)은 한 번에 한 작업만 그 구간을 실행하게 막는 장치다.

asyncio는 스레드가 하나라도 안전하지 않다. 대화 기록을 읽고 → `await`로 LLM을 기다리고 → 저장하는 사이에 다른 작업이 같은 기록을 읽을 수 있기 때문이다.

**이 프로젝트에서**: 같은 사용자가 메시지를 연달아 보내면 그 메시지들도 동시에 처리된다. 그래서 `agent.py`에 사용자별 잠금 도우미를 둔다. `async def reply`는 `async with user_lock(user_key):`, `def reply`는 `with user_thread_lock(user_key):` 안에서 상태를 읽고 고친다. 같은 사용자의 메시지는 받은 순서대로 하나씩, 다른 사용자끼리는 병렬로 처리된다. 잠금을 기다리는 시간도 [시간 예산](#타임아웃)에 포함된다.

### httpx
Python HTTP 클라이언트 라이브러리다. 비동기(`AsyncClient`)를 지원한다.

**이 프로젝트에서**: 콜백 API 호출에 쓴다.

### FastAPI와 uvicorn
FastAPI는 Python 웹 API 프레임워크이고, uvicorn은 FastAPI 앱을 실행하는 서버 프로그램이다.

**이 프로젝트에서**: 예비용 웹훅 서버(`main.py`)에만 쓴다.

### pytest
Python 테스트 도구다. `tests/` 폴더의 `test_*` 함수를 찾아 실행한다. 실행 명령은 `.venv/Scripts/python -m pytest -q`(Windows)다.

**이 프로젝트에서**: `tests/test_gateway.py`는 PC 안에 가짜 카카오 게이트웨이를 띄워서 핸드셰이크, 재연결, 종료 코드 처리를 검증한다.

### 가상환경(venv)
프로젝트마다 따로 쓰는 Python 패키지 설치 공간이다. `.venv/` 폴더에 있고, git에는 올리지 않는다.

## 안정성 설계

### 지수 백오프
Exponential backoff. 실패한 뒤 다시 시도할 때 **기다리는 시간을 2배씩 늘리는** 방법이다(1초 → 2초 → 4초 … 최대 10초). 서버가 장애 중일 때 요청을 퍼붓지 않기 위해서다.

**이 프로젝트에서**: `Gateway.run()`의 재연결 간격. 연결이 30초 이상 유지됐다가 끊기면 1초부터 다시 센다(`STABLE_CONNECTION_SEC`).

### 재시도와 일회용 토큰
요청이 실패했을 때 무조건 다시 보내면, 이미 처리된 요청이 두 번 처리될 수 있다. 콜백 토큰처럼 한 번만 쓸 수 있는 값은 특히 조심해야 한다.
- **연결 실패**(요청이 아예 나가지 않음)는 다시 보내도 안전하다.
- **응답을 못 받은 경우**(요청은 나갔을 수 있음)는 다시 보내지 않는다.

**이 프로젝트에서**: `bot.send_reply()`는 `ConnectError`, `ConnectTimeout`일 때만 재시도한다. 운영진 액션 서버를 부르는 `action_api.call()`도 같은 규칙이다(예약·등록 요청이 두 번 처리되지 않게).

### graceful shutdown
우아한 종료. 프로그램을 끌 때 **새 작업은 받지 않고, 진행 중인 작업은 마무리한 뒤 끄는** 것이다.

**이 프로젝트에서**: 종료 신호(SIGTERM)를 받으면 게이트웨이 연결을 닫고, 진행 중인 답장을 최대 280초까지 기다린다(`Gateway.drain()`). systemd 쪽도 `TimeoutStopSec=300`으로 기다려 준다.

## AWS와 서버 운영

### EC2
AWS의 가상 서버 서비스다. 원하는 사양의 리눅스 컴퓨터를 빌려서 계속 켜 둘 수 있다.

**이 프로젝트에서**: Ubuntu 인스턴스에서 `gateway.py`를 상시 실행한다. `t3.micro`(메모리 1GiB)로 시작하고, 당일 `agent.py`의 메모리 사용량을 보고 `t3.small`(2GiB)로 바꿀지 정한다([배포 가이드](deploy_ec2.md#인스턴스-크기-정하기)).

### 메모리 부족(OOM)과 스왑
OOM(Out Of Memory)은 메모리가 바닥난 상태다. 이때 리눅스의 OOM killer가 메모리를 많이 쓰는 프로세스를 골라 강제로 끝낸다. 프로그램은 오류 메시지 없이 갑자기 사라지고, 흔적은 `sudo dmesg | grep -i oom`이나 `journalctl -k`에 남는다.

스왑(swap)은 메모리가 모자랄 때 **디스크 일부를 메모리처럼 빌려 쓰는 공간**이다. 당장 쓰지 않는 메모리 내용을 디스크로 옮겨 자리를 만든다. 디스크는 메모리보다 훨씬 느리므로 스왑을 쓰는 동안은 느려지지만 강제 종료될 가능성은 줄어든다. 스왑까지 다 차면 여전히 OOM이 난다. 책상(메모리)이 꽉 차면 안 보는 서류를 서랍(스왑)에 넣어 두는 것과 같다.

**이 프로젝트에서**: Ubuntu EC2에는 스왑이 기본으로 없어서 2GB 스왑 파일을 만든다. 메모리가 순간적으로 넘쳐도 봇이 죽을 위험을 줄이는 안전장치다. 평소에도 스왑을 계속 드나든다면(`vmstat 1`의 `si`·`so`) 인스턴스를 키운다.

### 탄력적 IP
Elastic IP. EC2에 붙이는 **고정 공인 IP**다. 붙이지 않으면 인스턴스를 껐다 켤 때 IP가 바뀔 수 있다.

**이 프로젝트에서**: 카카오 [호출 허용 IP](#호출-허용-ip)에 등록하므로 IP가 바뀌면 안 된다. IP가 바뀌면 목록에 없는 IP가 되어 답장이 거부된다.

### 보안 그룹
EC2의 방화벽 규칙이다. 어떤 포트로 누가 들어올 수 있는지 정한다.

**이 프로젝트에서**: 인바운드는 SSH(22번)를 내 IP에만 연다.

### SSH
원격 서버에 안전하게 접속해 명령을 실행하는 방법이다. EC2는 키 파일(`.pem`)로 접속한다.

### systemd
리눅스에서 프로그램을 **서비스로 등록해 관리하는** 도구다. 부팅할 때 자동으로 실행하고, 죽으면 다시 살린다.
- `sudo systemctl start|stop|restart|status ai-top-100`
- 로그 보기: `journalctl -u ai-top-100 -f`
- `Restart=always`: 종료되면 항상 다시 실행한다.
- `RestartPreventExitStatus=2`: 종료 코드가 2이면 다시 실행하지 않는다(토큰 오류 같은 치명적 문제).
- `TimeoutStopSec=300`: 끌 때 최대 300초 기다린다.
- `OnFailure=`: 서비스가 실패 상태가 되면 지정한 다른 서비스를 실행한다. `Restart=`로 자동 재시작되는 실패에도 실행된다.
- 템플릿 유닛(`이름@.service`): 이름의 `@` 뒤에 값을 붙여 실행하는 서비스 틀이다. 안에서 `%i`로 그 값을 읽는다.

**이 프로젝트에서**: `deploy/ai-top-100.service`. 실패하면 `OnFailure=ai-top-100-alert@%n.service`가 `notify_failure.py`를 실행해 디스코드로 알린다(`%n`은 실패한 서비스 이름).

### 디스코드 웹훅
디스코드 채널에 글을 올리는 전용 URL이다. 이 URL로 HTTP POST를 보내면 채널에 메시지가 올라간다. 로그인이나 봇 설정이 필요 없어 알림 용도로 많이 쓴다. URL만 알면 누구나 글을 쓸 수 있으므로 비밀값으로 다룬다. (카카오의 [웹훅](#웹훅)과 이름은 같지만, 이것은 우리가 디스코드로 **보내는** 쪽이다.)

**이 프로젝트에서**: `.env`의 `DISCORD_WEBHOOK_URL`. 서비스가 실패하면 `notify_failure.py`가, 프로그램은 살아 있는데 답을 못 하는 상황(답장 연속 실패, 접속 장기 끊김, LLM 상태 확인·캐시 예열 실패, 크레딧 소진)이면 `alerts.py`가, 남은 크레딧 추정액이 줄어 절약 모드·멈춤 단계로 바뀌면 `cs_agent.py`가 이 URL로 알림을 보낸다.

### 종료 코드
프로그램이 끝날 때 남기는 숫자다. 0은 정상 종료, 나머지는 오류를 뜻한다.

**이 프로젝트에서**: `gateway.py`는 다시 시도해도 소용없는 오류(`BOT_TOKEN` 미설정, 4003)일 때 2(`EXIT_FATAL`)로 끝난다.

### 로그와 로그 로테이션
로그는 프로그램이 무슨 일을 했는지 시간순으로 남기는 기록이다. 계속 한 파일에 쌓으면 끝없이 커지므로, 일정 주기(예: 자정)마다 새 파일로 넘기고 오래된 파일은 지운다. 이것을 로그 로테이션이라고 한다.

**이 프로젝트에서**: `config.setup_logging()`이 화면과 `logs/bot.log`에 함께 남긴다. 자정마다 새 파일로 넘기고 지난 파일은 최근 14개까지 남긴다(`TimedRotatingFileHandler`). 기간이 아니라 개수 기준이라, 서버를 오래 꺼 두면 14일보다 오래된 파일이 남을 수 있다. 사용자 식별 정보가 섞일 수 있어 `logs/`는 git에 올리지 않는다. 메시지 내용은 남기지 않고, 메시지마다 결과와 처리 시간만 요약해 남긴다(`message seq=... result=...`).

## 기타

### 환경변수와 .env
환경변수는 프로그램 바깥에서 넣어 주는 설정값이다. 비밀값을 코드에 직접 쓰지 않기 위해 쓴다. `.env` 파일에 `이름=값` 형식으로 모아 두고, git에는 올리지 않는다. 형식 예시는 `.env.example`에 있다.

**이 프로젝트에서**: `BOT_TOKEN`, `ANTHROPIC_API_KEY`, `AGENT_TIMEOUT_SEC`, `LOG_PAYLOAD`. 프로그램이 시작할 때 `config.py`가 프로젝트 폴더의 `.env`를 읽는다(python-dotenv). 로컬과 EC2 모두 같은 방식이고, 같은 이름의 환경변수가 이미 설정돼 있으면 그 값이 우선한다.

### AI 에이전트
사용자 요청을 받아 LLM(대형 언어 모델)을 호출하고, 필요하면 도구(검색, 계산 등)를 써서 답을 만드는 프로그램이다. 대회에서는 이 에이전트를 카카오톡 챗봇 형태로 제출한다.

**이 프로젝트에서**: `agent.py`의 `reply(content, user_key)`. 문자열이나 SkillResponse를 돌려준다. 메시지마다 LLM을 한 번 불러 의도와 값을 뽑고(`llm.py`), 처리·거절·되묻기는 Python이 정하며(`policy.py`), 답은 템플릿으로 만든다. 필요한 값이 빠졌을 때는 바로 되묻지 않고, 받은 값만으로 답이 정해지는지(예: 없는 품목) 먼저 확인한다(`problem.precheck`). 문제 전용 내용은 `problem.py`에 모여 있고 지금은 시험용 예시다. `user_key`는 보낸 사람의 `botUserKey`로, 사용자별 대화 상태를 나누는 데 쓴다. 업무 권한을 증명하지는 않는다.

### LLM
Large Language Model. Claude, GPT처럼 글을 이해하고 만들어 내는 대형 AI 모델이다. 보통 HTTP API로 호출하며, 응답에 수 초에서 수십 초가 걸릴 수 있다.

### 구조화 출력
LLM의 답을 정해진 JSON 형식(JSON 스키마)에 맞게 강제하는 기능이다. 자유 문장 대신 `{"intent": "lookup", "slots": {...}}` 같은 값을 받아 코드가 바로 쓸 수 있다. 그래도 답이 잘리거나(`max_tokens`) 거절되면 형식이 깨질 수 있어 코드에서 한 번 더 검사한다.

**이 프로젝트에서**: `llm.extract`가 `output_config.format`으로 요청하고 `check_schema`로 다시 본다. 어긋나면 `format_error`로 처리해 사용자에게 다시 말해 달라고 안내한다.

### 도구 호출(tool use)과 TC ID

LLM이 답을 쓰는 중에 "이 함수를 이 값으로 불러 달라"(`tool_use`)고 요청하면, 프로그램이 실제로 실행해 결과(`tool_result`)를 돌려주고 LLM이 이어서 판단하는 방식이다. 이 프로젝트에서는 운영진 액션 API(주문 조회, 환불 신청, 담당자 이관 등)가 도구다(`cs_tools.py`). LLM이 무엇을 부를지는 정하지만, 부를 수 있는 대상(본인 주문만, 보상 쿠폰만)은 코드가 막는다. 반복 횟수(4회, 절약 모드 3회)와 시간(50초)에 상한을 둔다.

TC ID는 심사 사례(test case) 번호다(예: `T-03`). 액션 API는 요청마다 정해진 헤더(`ACTION_TC_HEADER`)에 이 값을 넣어야 하고, 평가 때는 대화로 전달받은 값을 한 사례 동안 그대로 쓴다. 에이전트는 메시지에서 찾아 사용자별로 기억하고, 다른 TC ID가 오면 상담을 새로 시작한다.

### 프롬프트 캐시와 예열
LLM에 매번 보내는 긴 앞부분(규칙, 지식, 도구 정의)을 서버가 잠시 기억해 두고, 다음 요청에서 같은 앞부분이 오면 다시 계산하지 않는 기능이다. 처음 기억시키는 "쓰기"는 일반 입력보다 비싸고, 기억된 것을 쓰는 "읽기"는 훨씬 싸고 빠르다. 기억은 정해진 시간(이 프로젝트는 1시간) 동안 쓰이지 않으면 사라지고, 읽힐 때마다 다시 늘어난다. 여러 요청이 동시에 처음 오면 각자 "쓰기"를 해서 비용이 커진다.

**이 프로젝트에서**: 지식이 약 25만 토큰이라 캐시가 비용을 좌우한다. `cs_agent.warm_cache`가 5분마다 확인해, 같은 모델로 50분 넘게 호출이 없을 때만 짧은 요청(출력 32토큰)으로 캐시를 데워 두어(실제 답변 호출도 캐시 수명을 늘리므로 그동안은 건너뛴다), 심사 대화가 동시에 시작돼도 "읽기"가 되게 한다. 이 요청은 실제 토큰을 쓰므로 크레딧 소진도 함께 잡는다(`[크레딧 소진]`·`[LLM 이상]` 알림). 캐시는 모델마다 따로라서, 절약 모드에서는 Haiku 캐시를 데우고 멈춤 단계에서는 데우지 않는다.

### 프롬프트 인젝션
사용자 입력 안에 "이전 지시를 무시해" 같은 지시를 넣어 LLM이 원래 규칙을 어기게 하려는 시도다. 시스템 프롬프트로 "따르지 마라"고 써도 완전히 막을 수 없다.

**이 프로젝트에서**: 코드에서 막는다. LLM이 낸 의도·값은 `problem.py`에 정의된 것만 쓰고, 값은 형식(`SLOT_PATTERNS`)을 통과해야 조회에 쓰인다. 데이터 답변은 템플릿으로 만들어 LLM 문장이 끼어들지 않는다. 타인·다수 정보는 권한 주장만으로 주지 않는다(`problem.is_authorized`).
